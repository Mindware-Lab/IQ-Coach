# IQ Mindware Adaptive Journey Specification v0.1

**Status:** Shared product/narrative contract  
**Date:** 22 September 2026  
**Repository:** `Mindware-Lab/IQ-Coach`  
**App:** `apps/iqm-platform/`

## Purpose

Every Synergy IQ node should be experienced as a chapter in one adaptive-intelligence curriculum, not as an isolated brain-training game.

The platform should guide the user through:

```text
VISION
Navigate possibility. Build intelligence.
Turn possibility into agency.

↓

CHAPTER
What adaptive problem does this capacity solve?

↓

CAPACITY
Train the underlying operation.

↓

INVARIANT
What useful structure survives surface change?

↓

STRATEGY
Turn the operation into a memorable portable move.

↓

NICHE
Recognise the same demand in work, learning, social/digital or AI contexts.

↓

REALITY
Use it in one consequential real situation.

↓

FEEDBACK
What actually happened?

↓

BANK
What rule should be kept?

↓

RE-ENTER
Meet the next challenge from a richer starting point.
```

## Evidence separation

The platform must preserve four distinct layers:

1. **Training performance** — what happened inside the game.
2. **Changed-surface / transfer probes** — whether the operation survives wrapper change and return.
3. **Mission feedback** — self-reported implementation feedback from a real setting.
4. **G Track / external measurement** — separate adaptive profile and cognitive benchmarks.

Mission feedback must never be automatically relabelled as scientific transfer evidence.

## Node journey contract

A node may provide:

- chapter number/title;
- human question;
- worldview hook;
- portable move;
- rationale for abstract training;
- narrative meanings for anchor / perturb / return / salience / banking events;
- reality mission prompt;
- banking prompt.

The platform shell owns rendering and progression between these surfaces.

## Attention Control — Chapter 01 · Signal

**Human question:** What matters now?

**Worldview hook:** The world is very good at making things feel important. Attention Control distinguishes what is salient from what is relevant to the goal the user actually owns.

**Portable move:** Pause. Find the signal. Commit.

### APR narrative

```text
ANCHOR
Find the signal.

PERTURB
Same skill. Different world.

RETURN
Can you recover it?

SALIENCE CHALLENGE
What grabs attention is not always what deserves it.

FINAL RETURN / BANK
Bank the skill.
```

In the forced QA programme these map to:

```text
Static/Polar
→ Optic Flow
→ Static return
→ Emotional Distractor
→ Static return
```

Production progression should eventually trigger narrative events from actual APR/progression events rather than hard-coded session numbers.

## Guided journey priority

The node home should answer one question first:

> **What is my next useful step?**

Primary journey precedence:

```text
chapter not understood
→ understand

no training yet
→ train

strategy not extracted
→ learn portable move

no real mission
→ choose mission

mission not reviewed
→ reality check-in

feedback not banked
→ bank reusable rule

otherwise
→ continue training / next perturbation
```

Secondary tools such as training history, AI practice, missions, G Track, Arena or QA controls should be discoverable but subordinate to the primary journey.

## Reality check-in

A mission check-in asks:

- Did the opportunity occur?
- Did the strategy get used?
- What was the effect?
- Did the niche/environment change help?
- What got in the way?
- Anything worth remembering?

If the opportunity did not occur, this is not a failure. Reschedule or choose another context.

## Banking

Banked learning uses:

```text
WHEN ...
I WILL ...
BECAUSE ...
```

A banked rule is a personal learning artefact, not a psychometric score or causal training claim.

## AI / Generative Cognitive Niche

AI practice should preserve:

```text
HUMAN FIRST
own the goal and initial judgement

↓

AI SUPPORT
let the tool generate / shortlist / organise

↓

HUMAN REVIEW
correct omissions and false positives

↓

FRESH UNAIDED CHECK
test what remains without the scaffold
```

The user-facing lesson is:

> Supported performance is not the same as retained capability.

The product should not frame AI as intrinsically harmful. The design question is whether the configuration expands useful cognition while preserving purpose, evidence judgement, commitment and learning.

## Seven-node chapter spine

| Node | Chapter idea | Human question | Portable move |
| --- | --- | --- | --- |
| Attention Control | Signal | What matters now? | Pause. Find the signal. Commit. |
| Relational Memory | Structure | What is connected to what? | Hold the relation, not every detail. |
| Binding Memory | Context | What belongs with what? | Keep claim, source and context together. |
| Path Horizon | Consequence | Where does this lead? | Look one or two states ahead. |
| Knowledge Access | Retrieval | What do I already know that matters here? | Retrieve first. Then scaffold. Then check what remains. |
| Generative Search | Possibility | What else could be true or possible? | Generate distinct alternatives before choosing. |
| Reasoning | Constraint | What actually follows? | Constrain with evidence; test what would change the conclusion. |

This table defines narrative orientation, not validated psychometric factor structure.
